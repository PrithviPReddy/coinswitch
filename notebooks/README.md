# Training the cost model in Colab

`train_cost_model.ipynb` fits CoinSwitch's cost model and writes
`cost-model.json` in the format of `models/cost-model.schema.json`. It runs in
Google Colab, never on the development machine. The repository needs no local
Python install.

## 1. Export the dataset (on the dev machine)

```bash
npm run export:samples
```

This writes three files to `exports/`, which is gitignored:

| File | What it is |
|---|---|
| `quote_samples.csv.gz` | every QuoteSample row: ladders, notionalUsd, measuredImpactBps, routes, slots |
| `quote_drift.csv.gz` | every QuoteDrift row, including actualElapsedMs |
| `export_manifest.json` | row counts, column list, sign conventions, the collection-phase timestamps |

Raw columns only. Every feature is derived inside the notebook, in one place.

## 2. Run the notebook (in Colab)

1. Open `notebooks/train_cost_model.ipynb` in Colab (File > Upload notebook).
   A CPU runtime is fine.
2. **Runtime > Run all.**
3. Cell 1 asks for the three files: upload them. To read them from Google
   Drive instead, set `USE_DRIVE = True` and put them in `DRIVE_DIR`.

It uses only pandas, numpy, scikit-learn and matplotlib, all of which Colab
ships, so there are no pip installs.

What it does, in order:

- data quality: collection gaps and ladder span by phase
- **drift coverage** (pair class × horizon, before and after the limiter fix),
  with the +5 s row called out
- the volatility feature, computed exactly as the app computes it
- a **time-based** train/test split (70/30 by time, never random)
- the **impact table** recomputed over all data, deep and thin separately,
  plus impact curves on log axes
- power-law impact per pair with a ridge baseline. Each pair may instead
  get a continuous two-segment power law (a hinge in log-log space, with
  the knot at a rung), kept only if it beats the single line on the latest
  20% of that pair's training rows when both are fitted on the earliest 80%.
  The test split is never used to choose. Test MAE is reported for both,
  overall and at $200k and up.
- a ridge drift model with a train-mean baseline; empirical failure
  probabilities
- test-period metrics with **an n on every number**, a calibration table, and
  gradient-boosted trees for comparison only
- the **directional test** (does B/A drift mirror A/B?) wherever both
  directions were sampled
- self-test and feature-test vectors, then `cost-model.json`

## 3. What comes back

The browser downloads two files:

- `cost-model.json`: the artifact.
- `coinswitch_cost_model_outputs.zip`: the same artifact, the figures
  (`fig_impact_curves.png`, `fig_drift_by_horizon.png`,
  `fig_predicted_vs_actual.png`), and the report tables as CSV (drift
  coverage, impact table, directional test).

The last cell prints a plain-text summary. Paste it back.

## 4. Where to put it (on the dev machine)

```bash
cp ~/Downloads/cost-model.json models/cost-model.json
npm run validate:model
```

`validate:model` checks the artifact against the schema. It then re-runs
every self-test vector through the TypeScript inference code
(`app/lib/costModel.ts`), and every feature-test vector through the
TypeScript feature code. If a number disagrees with what the notebook
computed, it fails. That is the guard against the notebook and the app
quietly computing different things. Don't serve a model that fails it.

## Notes

- The model is fitted on the **training period only**, so the held-out
  period stays clean for the backtest (P5).
- `models/cost-model.example.json` was made by a TypeScript reference fit of
  the same methods (`npm run fit:example-model`). It is an example for
  development, not the cost model. Its metrics are a useful sanity check
  against the notebook's own.
- `notebooks/train_cost_model.ipynb` is generated by
  `npm run build:notebook` from `scripts/build-notebook.mjs`. Edit the
  generator, not the notebook.
